# Digital Product Marketplace — Starter Plan & App Blueprint

> This document is a complete starter guide for a Digital Product Marketplace (think Gumroad / Gumtree for digital goods). It includes: a recommended tech stack, features, data models, API surface, frontend pages, deployment notes, and next steps to turn this into a working codebase.

## 1 — Project overview

A **Digital Product Marketplace** lets creators upload and sell digital products (ebooks, templates, audio, images, code, courses, plugins). Buyers browse, purchase, and download instantly. Platform features include payments, file hosting, versioning, licensing, analytics, and seller dashboards.

Target users:
- Creators (sellers) who list digital products
- Buyers who search, purchase, and download
- Admins who moderate content and manage payouts

Goals for the starter implementation:
1. User accounts + authentication
2. Seller product uploads with file hosting
3. Product listing, search & categories
4. Payment flow (checkout, webhooks, receipts)
5. Delivery (secure download links or gated access)
6. Basic seller dashboard & analytics
7. Admin moderation panel

---

## 2 — Recommended tech stack (starter)

- Backend: **Laravel (PHP)** — great for marketplaces, batteries-included, fast to build. (Alternatively: Node.js + NestJS)
- Frontend: **Next.js (React + TypeScript)** — SSG/SSR for marketing pages and dynamic buyer flows
- Database: **Postgres**
- File storage: **S3-compatible** (AWS S3, DigitalOcean Spaces)
- Payments: **Stripe** (supports payouts, webhooks, connected accounts)
- Background jobs: **Laravel Queues** (Redis)
- Search: **Postgres full-text** for MVP, later Algolia/Elastic
- Containerization: **Docker**

---

## 3 — High-level architecture

- Next.js app for marketing, product browsing, and buyer checkout.
- Laravel API for authenticated actions (product CRUD, file uploads, orders, payouts).
- S3 for file storage; signed URLs generated by backend for secure downloads.
- Stripe for payments and payouts (use Stripe Connect for marketplace payouts).
- Redis + Queue workers for processing uploads, generating thumbnails, virus scanning jobs.

---

## 4 — User roles & flows

### Roles
- Guest: browse products
- Buyer: purchase and download
- Seller: upload/manage products, view sales
- Admin: moderate, manage disputes

### Core flows (buyer)
1. Browse product → View product page → Add to cart → Checkout (Stripe) → On success, receive email and access to download
2. Download link generated with expiry + one-time token

### Core flows (seller)
1. Register as seller (KYC optional) → Upload product (title, description, price, file) → Product goes through optional moderation → Product published
2. View sales, request payout (Stripe Connect)

## 5 — Database schema (core tables)

```sql
users
- id, name, email, password_hash, role, stripe_account_id, created_at

products
- id, seller_id (FK users), title, slug, description, price_cents, currency, category, status (draft/pending/published), thumbnail_url, created_at

product_files
- id, product_id, filename, s3_key, size_bytes, mime_type, version, checksum, created_at

orders
- id, buyer_id, product_id, amount_cents, currency, stripe_payment_id, status, created_at

downloads
- id, order_id, token, expires_at, used_at

payouts
- id, seller_id, amount_cents, stripe_transfer_id, status, requested_at, completed_at
```

## 6 — API surface (selected endpoints)

**Auth**
- `POST /api/auth/register`
- `POST /api/auth/login`
- `POST /api/auth/refresh`

**Products**
- `GET /api/products` — list, filters, search
- `GET /api/products/:slug` — product details
- `POST /api/seller/products` — create product (multipart for file)
- `PUT /api/seller/products/:id` — update product
- `DELETE /api/seller/products/:id`

**Orders & Payments**
- `POST /api/checkout` — create checkout session (returns Stripe session id)
- `POST /api/webhooks/stripe` — stripe webhook handler
- `GET /api/orders/:id/download` — returns signed download URL (auth + token)

**Seller dashboard**
- `GET /api/seller/sales` — returns sales, revenue
- `POST /api/seller/payouts` — request payout

**Admin**
- `GET /api/admin/products?status=pending`
- `POST /api/admin/products/:id/approve`

## 7 — Security & content protection

- Store original files in private S3 bucket.
- Generate short-lived signed URLs (e.g., 10 minutes) for download.
- Attach download token to each order and limit downloads per purchase.
- Optional watermarking or license key generation for sensitive assets.
- Virus scan uploads using a worker (ClamAV) before changing product status to published.
- Rate-limit download endpoints and validate referer/user tokens.

## 9 — Development setup (local)

1. Install Docker & Docker Compose.
2. Copy `.env.example` to `.env` for backend and frontend.
3. Start services: `docker compose up --build`
4. Run migrations: `php artisan migrate`
5. Start Next dev server: `npm run dev` in `web` folder.
6. Configure Stripe webhook in local tunnel (ngrok) to `POST /api/webhooks/stripe`.

---

## 10 — Deploy notes

- Use managed Postgres (e.g., AWS RDS, Supabase) and S3 for file storage.
- Deploy Laravel on a container service (ECS, DigitalOcean App Platform) or using Forge.
- Next.js can be deployed to Vercel for CDN benefits.
- Enable background workers for processing uploads and webhooks.
- Configure Stripe Connect with onboarding flow for sellers.

## 13 — Example: minimal Laravel route for generating signed download

```php
Route::get('/api/orders/{order}/download', function (Order $order) {
    $user = request()->user();
    if ($order->buyer_id !== $user->id) abort(403);

    $fileKey = $order->product->primaryFile->s3_key;
    $url = Storage::disk('s3')->temporaryUrl($fileKey, now()->addMinutes(10));
    return response()->json(['url' => $url]);
});
```
